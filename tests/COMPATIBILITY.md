# Compatibility report — SWFReader 0.6.0 · RetroFlash 1.0.0-beta.2

This file lists only what the tests demonstrate. Anything that is not listed here is unverified.

## How to verify

```sh
node tests/run.js                        # all tests (Node 16+, no npm install)
npm run test:dist                        # the same tests against the versioned bundle in dist/ (needs npm install)
node tests/fixtures/build-fixtures.js    # regenerate the fixtures after changing the catalog
node tests/inspect.js some.swf --tags    # inspect any SWF from the command line
npm run corpus:fixtures                  # regenerate the fixture matrix (tests/corpus/fixtures-matrix.*)
node tools/corpus.js some.swf folder/    # the compatibility matrix of any SWF files you may use
```

| Environment | `DecompressionStream` | Result (2026-10-28) |
|---|---|---|
| Node 16.15.0 (Windows) | test-only zlib polyfill (`tests/support/load-reader.js`) | 221 passed, 0 failed (sources and `dist` bundle) |
| Node 22.13.0 (Windows) | native | 221 passed, 0 failed (sources and `dist` bundle) |
| Chrome (headless, Windows) | native | Manual run of `demo/player.html`; see “Rendering” below. Not automated |

The runtime does not ship the polyfill. In Node, it lets the reader's real streaming code run where the global is missing.

## Fixtures

All fixtures are generated by [`fixtures/build-fixtures.js`](fixtures/build-fixtures.js), using the project's own test writer ([`support/swf-builder.js`](support/swf-builder.js)). They contain no third-party content. `unit/fixtures.test.js` checks two things for each file:

- the committed file still matches the generator. Compressed files are compared by header and inflated content, because zlib output can vary between versions;
- loading the file gives exactly the outcome listed below: the same error code, or the same header values, top-level tag count, diagnostic codes, and unsupported features.

### Cases without fixture files

These are covered in `unit/*.test.js`:

- **Bit reader:** RECT, MATRIX, CXFORM, and CXFORMWITHALPHA vectors worked out by hand from the specification, independently of the test writer; UB/SB/FB widths 0, 1, 17, and 32; sign extension; fields that span byte boundaries; alignment; reads never cross the reader's end; invalid widths and ranges; and 300 seeded random round trips that start unaligned.
- **Limits:** `maxFileBytes` (for buffers and Blobs), `maxTags` (nested tags included), `maxSpriteDepth` 0 and 1, and option validation.
- **API:** inputs as Uint8Array, ArrayBuffer, Buffer, DataView, and Blob; `getTagData` with valid tags (top-level and nested) and invalid ones; `walkTags`.
- **Version-dependent behavior:** strings are Latin-1 before SWF 6 and UTF-8 from SWF 6; the FrameLabel named-anchor flag is read only from SWF 6; FileAttributes must be present and first from SWF 8; CWS in files older than SWF 6; the AVM2 flag; a stage RECT with min > max; CWS when `DecompressionStream` is missing (`CWS_UNSUPPORTED`).
- **Robustness** (`robustness.test.js`, SWFs built in memory):
  - a button that contains itself twice per level;
  - 25 distinct sprites that each place the next one twice (2^25 instances without limits): stopped by the instance budget in bounded time;
  - pressing outside a button and releasing over it;
  - a hit-area sprite with a `stop()` frame script;
  - a `PlaceObject3` with an unknown filter id;
  - a `DefineButton2` with a gap before its actions;
  - an undecodable `DefineBitsLossless` that is placed;
  - `inflate` in strict and truncate modes;
  - `DefineFunction` and `DefineFunction2` followed by `stop()`: the body after the record is skipped and `stop()` runs;
  - image header sizes (JPEG `SOF0`/`SOF2` after `APP0`, PNG, GIF; scan before frame header, missing marker);
  - per-bitmap and per-movie pixel budgets, and a JPEG declaring 30000×30000 refused before decoding;
  - two overlapping `load()` calls where the older one finishes last; a load superseded while decoding a bitmap, whose decoding failure must not reach the newer movie's diagnostics; and a failed load after `destroy()` (headless canvas stand-in);
  - player limits: defaults, overrides, invalid values (`INVALID_OPTION`), and `maxNesting`, `maxInstances`, `maxActionBlocks`, and `maxActionSteps` each cutting a movie built for it (`maxActionStack`: see the stack core below);
  - one action budget per tick, shared by the frame scripts and the roll-over of a button that appears under the pointer, and a new budget for the next input event;
  - the decoding budget across 30 blocks and an empty one, with a lowered budget:
    - the first 10 blocks run; the 11th crosses the threshold with its `Push` and stops at its `Pop`; every later block stops;
    - the cost counted matches what the cache holds (records plus the block cost);
    - blocks that decoded nothing, and the empty block, are not cached;
    - on the second loop, the cached blocks run again, and nothing new is decoded or cached.
- **AVM1 decoder** (`avm1-decoder.test.js`, byte layouts worked out by hand from the specification):
  - record boundaries up to `ActionEndFlag`, and the bytes after it;
  - the operands of every action that has them:
    - `Push` values of every type, including the word order of doubles and negative integers;
    - the flags of `GetURL2` as Flash Player writes them (`0x80` variables, `0x40` into a clip, the method in the low bits, 3 read as none), `GotoFrame2`, `DefineFunction2`, and `Try`;
    - function, `With`, and `Try` bodies;
  - branch targets measured from the next record, back to the start, at the end of the block, outside it (`INVALID_BRANCH`), and inside another record;
  - strings decoded as Latin-1 before SWF 6 and as UTF-8 from SWF 6;
  - the SWF version that introduced each action, and unknown codes;
  - errors: `TRUNCATED_RECORD`, `INVALID_OPERANDS`, `INVALID_RANGE`, and offsets outside the block;
  - a budget shared by two blocks: each record counted once, by its length, plus the block cost; `DECODE_BUDGET` once it is spent, with the decoded records still available;
  - the threshold: the record that crosses it is kept, and the next one is refused. Records with errors (a `Push` that declares 65,535 bytes in a shorter block, an unknown `Push` type, a cut header) cost at most their header;
  - in the interpreter: a malformed `GotoFrame` or function body ends the script, while a malformed action outside the subset is still reported and skipped.
- **AVM1 stack core** (`avm1-stack.test.js`, one action block per test, stack and registers checked after it runs):
  - `Push` of every value type, in order; `Pop`, `PushDuplicate`, and `StackSwap`;
  - underflow giving `undefined`, including a `StackSwap` with one value;
  - `StoreRegister` copying the top without popping it, on an empty stack, and to registers past 3 (ignored); `Push` of registers 0–3 and of missing ones;
  - the constant pool read by 8- and 16-bit index, replaced by a later pool, read before any pool, and past its end;
  - skipped actions with fixed counts (`GetMember`, `TargetPath`, `Extends`, `SetProperty`) leaving unknown values; `InitArray` leaving the whole stack unknown; unknown action codes without effect; function literals;
  - a malformed `Push` (unknown type, truncated double), `StoreRegister`, or `ConstantPool` ending the script;
  - `maxActionStack`, checked on every push: a `Push` of five values with a limit of 2 never holds a third, and neither do `PushDuplicate`, `StackSwap` on an empty stack, skipped actions, or function literals;
  - lazy decoding: with `maxActionSteps` 10, a block of 5,000 actions decodes at most 10 records and is never listed; a truncated record is reported when the script reaches it, and not when an earlier action ends the script;
  - the stack-effect table listing only actions that are skipped (no operator or variable action).
- **AVM1 values** (`avm1-values.test.js`, a matrix of values by SWF version 4, 5, 6, and 7):
  - to number: `undefined` and `null`, booleans, and strings with whitespace, signs, points, exponents, trailing text, hexadecimal (with a sign, past 32 bits, empty, or invalid), octal, and `"Infinity"`;
  - to string: `undefined`, booleans, and numbers, including integers past 32 bits, 15-digit rounding, `0.1 + 0.2`, exponent forms at 1e15 and below 1e-5, NaN, the infinities, and the largest number;
  - to boolean: numbers and strings before and from SWF 7;
  - `Equals2`, `StrictEquals`, and `Less2` on mixed types, NaN, and `undefined` by version; `TypeOf`.
- **AVM1 expressions and variables** (`avm1-expressions.test.js`; operators in one block, variables in frame scripts of SWFs built in memory):

  - every SWF 5–7 operator, including `Add2` with `undefined` in SWF 6 and 7, shift counts past 31, and the signed `BitURShift` of SWF 8 and 9;
  - `RandomNumber` with a fixed source; unknown operands giving unknown results; `Trace`;
  - variables set and read from the root and from a child: plain names, `/:b`, `kid:c`, `kid.d`, `_root.kid.e`, `/kid:f`, `../:x`, `_parent.x`; a property (`_x`, reported), a movie clip and a slash path read as unknown values, and a missing path (nothing set);
  - case-insensitive names in SWF 6 and case-sensitive ones in SWF 7; SWF 4 paths (`.` splits only for `SetVariable`; a clip reads as `undefined`);
  - `SetTarget` scoping variables, an invalid target scoping them to the root, `DefineLocal`, and `DefineLocal2` (plain and with a path);
  - values kept between frames (`n = n + 1`), and a name that is an unknown value (reported, nothing set);
  - bound text fields: initial text initializing the variable, numbers shown as text, the renderer laying out a field again only when its text changes, an existing variable winning over the initial text, a path to a child's variable, an empty field creating no variable, an HTML field, and an unknown value keeping the last text.

## Compatibility corpus

[`tools/corpus.js`](../tools/corpus.js) runs SWF files through the reader and the player in Node and writes a matrix: one row per file, one column per layer.

| Layer | What lands there |
|---|---|
| Parser | Reader diagnostics, tags the reader does not decode, `timeline:` placement errors, files it rejects |
| VM | The AVM1 interpreter: budgets, malformed or unknown actions, unknown names and values, uncaught throws; ActionScript 3 movies |
| API | Built-in objects not implemented (`avm1:objectValue`), page interactions without a host or refused by it (`browser:`), sounds that cannot be played (`sound:`; the corpus plays them into a silent output) |
| Render | Characters or features not drawn (`render:`, `text:`), exceptions while drawing |
| Input | Buttons and pointer handling |

A layer is `ok`, `partial` (something was reported), or **failed** (an exception or a rejected file stops the run). Every run is the same: the clock advances one frame per tick, `random` follows a fixed sequence, 60 frames run (`--frames N`), and halfway the pointer moves to the stage centre, presses, and releases. Bitmaps are not decoded and drawing goes to a stand-in canvas, so pixels are not compared; that stays a manual check in Chrome. `--json` writes every field (hash, tags, action counts, features by layer).

The matrix of the project's fixtures is committed as [`corpus/fixtures-matrix.md`](./corpus/fixtures-matrix.md) (and `.json`), and `corpus.test.js` fails when it changes. Third-party files are never committed: run the tool on them locally. `visita.swf` (see below) gives `ok` in every layer with 16 AVM1 steps. With `--resources DIR`, a URL a script loads is answered with the file of `DIR` named like its last path segment; images are then only checked by their header, and the bitmaps of loaded movies are not decoded, as for the main movie.
