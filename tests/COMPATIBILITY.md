# Compatibility report — SWFReader 0.5.0 · RetroFlash 0.4.0

This file lists only what the tests demonstrate. Anything that is not listed here is unverified.

## How to verify

```sh
node tests/run.js                        # all tests (Node 16+, no npm install)
node tests/fixtures/build-fixtures.js    # regenerate the fixtures after changing the catalog
node tests/inspect.js some.swf --tags    # inspect any SWF from the command line
```

| Environment | `DecompressionStream` | Result (2026-10-27) |
|---|---|---|
| Node 16.15.0 (Windows) | test-only zlib polyfill (`tests/support/load-reader.js`) | 122 passed, 0 failed |
| Node 22.13.0 (Windows) | native | 122 passed, 0 failed |
| Chrome (headless, Windows) | native | Manual run of `demo/player.html`; see “Rendering” below. Not automated |

The runtime does not ship the polyfill. In Node, it lets the reader's real streaming code run where the global is missing.

## Fixtures

All fixtures are generated by [`fixtures/build-fixtures.js`](fixtures/build-fixtures.js), using the project's own test writer ([`support/swf-builder.js`](support/swf-builder.js)). They contain no third-party content. `unit/fixtures.test.js` checks two things for each file:

- the committed file still matches the generator. Compressed files are compared by header and inflated content, because zlib output can vary between versions;
- loading the file gives exactly the outcome listed below: the same error code, or the same header values, top-level tag count, diagnostic codes, and unsupported features.

### Cases without fixture files

These are covered in `unit/*.test.js`:

- **Bit reader:** RECT, MATRIX, CXFORM, and CXFORMWITHALPHA vectors worked out by hand from the specification, independently of the test writer; UB/SB/FB widths 0, 1, 17, and 32; sign extension; fields that span byte boundaries; alignment; reads never cross the reader's end; invalid widths and ranges; and 300 seeded random round trips that start unaligned.
- **Limits:** `maxFileBytes` (for buffers and Blobs), `maxTags` (nested tags included), `maxSpriteDepth` 0 and 1, and option validation.
- **API:** inputs as Uint8Array, ArrayBuffer, Buffer, DataView, and Blob; `getTagData` with valid tags (top-level and nested) and invalid ones; `walkTags`.
- **Version-dependent behavior:** strings are Latin-1 before SWF 6 and UTF-8 from SWF 6; the FrameLabel named-anchor flag is read only from SWF 6; FileAttributes must be present and first from SWF 8; CWS in files older than SWF 6; the AVM2 flag; a stage RECT with min > max; CWS when `DecompressionStream` is missing (`CWS_UNSUPPORTED`).
- **Robustness** (`robustness.test.js`, SWFs built in memory):
  - a button that contains itself twice per level;
  - 25 distinct sprites that each place the next one twice (2^25 instances without limits): stopped by the instance budget in bounded time;
  - pressing outside a button and releasing over it;
  - a hit-area sprite with a `stop()` frame script;
  - a `PlaceObject3` with an unknown filter id;
  - a `DefineButton2` with a gap before its actions;
  - an undecodable `DefineBitsLossless` that is placed;
  - `inflate` in strict and truncate modes;
  - `DefineFunction` and `DefineFunction2` followed by `stop()`: the body after the record is skipped and `stop()` runs;
  - image header sizes (JPEG `SOF0`/`SOF2` after `APP0`, PNG, GIF; scan before frame header, missing marker);
  - per-bitmap and per-movie pixel budgets, and a JPEG declaring 30000×30000 refused before decoding;
  - two overlapping `load()` calls where the older one finishes last; a load superseded while decoding a bitmap, whose decoding failure must not reach the newer movie's diagnostics; and a failed load after `destroy()` (headless canvas stand-in).
- **Text** (`text.test.js`, SWFs built in memory):
  - a DefineFont whose codes, name, and style come from DefineFontInfo;
  - a DefineText without its end byte (`TEXT_END_MISSING`), and a DefineFont2 glyph offset past the tag (`INVALID_OFFSET`, tag invalid);
  - HTML edge cases: mismatched end tags, entities, relative and clamped `<font size>`, whitespace-only text up to SWF 7, forced multiline up to SWF 6, and `<img>` reported;
  - hostile text in bounded time: 200,000 unclosed `<a`, a tag with 50,000 unterminated quotes, 100,000 unterminated comments, and a line with 200,000 spaces;
  - field formats: no inherited bold in HTML, left alignment before SWF 8, the Times New Roman 12 px default, and CSS families for device names (generic fallbacks; quotes and braces removed).

  Layout tests use a deterministic stand-in for device-font measurement, so they check the layout rules, not a browser's fonts.
- **Controlled fuzz:** every byte of `fws-timeline.swf` is mutated 5 ways, and the file is truncated at every length with its declared length adjusted. Each attempt must either load or reject with an `SWFReaderError`; no other exception type is allowed.

## Tag support

| Status | Tags |
|---|---|
| Decoded | `DefineShape`, `DefineShape2`, `DefineShape3`, `DefineShape4`, `DefineBits`, `JPEGTables`, `DefineBitsJPEG2`, `DefineBitsJPEG3`, `DefineBitsJPEG4`, `DefineBitsLossless`, `DefineBitsLossless2` (headers; the player decodes the pixels), `DefineButton`, `DefineButton2`, `DefineButtonCxform`, `DefineButtonSound` (button id only), `DefineFont`, `DefineFont2`, `DefineFont3`, `DefineFontInfo`, `DefineFontInfo2`, `DefineFontName`, `DefineFontAlignZones` and `CSMTextSettings` (ids and mode bits only), `DefineText`, `DefineText2`, `DefineEditText`, `End`, `ShowFrame`, `SetBackgroundColor`, `FrameLabel`, `FileAttributes`, `PlaceObject`, `PlaceObject2`, `PlaceObject3`, `RemoveObject`, `RemoveObject2`, `DefineSprite` (SpriteID, FrameCount, and recursive control tags) |
| Partial | `PlaceObject2`/`PlaceObject3` clip actions, listed in `unsupported`. Filter lists are validated and skipped; only the filter names are kept |
| Detected, never executed | `DoAction`, `DoInitAction` (AVM1), `DoABC` (AVM2) |
| Indexed only (offsets + `getTagData`) | Every other named tag: `DefineFont4`, sounds, video, morphs, `SymbolClass`, `Metadata`, … |
| Unknown | Any code missing from `SWFReader.tagNames`; skipped using its declared length |
| Rejected | `ZWS` files (LZMA) |

## Rendering (manual check, not automated)

`demo/player.html` was driven in headless Chrome over the DevTools protocol on 2026-10-27, and screenshots of the canvas were inspected by eye. With `valid/fws-animation.swf`, frames 1, 20, and 40 showed every element of the fixture as authored:

- the two-colour tile split along its shared edge;
- the circle with its gradient and the radial-gradient star;
- the zigzag with round caps;
- the stripes visible only inside the circular mask;
- the square rotated and faded;
- the tile gone at frame 40.

With `valid/fws-bitmaps.swf` (player 0.2), every tile showed as authored:

- the JPEG; the JPEG3 cut to a circle by its alpha plane; the DefineBits + JPEGTables tile, identical to the JPEG; the PNG alpha ramp over the yellow band;
- the pixelated (non-smoothed) palette bitmap; the 15-bit and 24-bit gradients; the Lossless2 alpha ramp;
- the repeating checker with transparent cells;
- the rotated half-alpha tile.

With `valid/fws-actions.swf`, the player reports root frame 5 with `rootPlaying: false`.

With `valid/fws-buttons.swf` (player 0.3), real input was sent over the DevTools protocol (`Input.dispatchMouseEvent` / `dispatchKeyEvent`):

1. Hover: the button shows its *over* state, the lamp lights up, and the cursor becomes a hand.
2. Press: the button shows *down*.
3. Release: the root goes to frame 2, where the green bar appears.
4. The tinted v1 button takes the root back to frame 1.
5. Enter takes the root to frame 2 again.

Screenshots matched each state.

With `valid/fws-text.swf` (player 0.4), every element showed as authored:

- the static text "HI O" in red and "OH" in blue one line lower, with the hole of the O open;
- the translucent green "III" drawn from the DefineFont3 glyph;
- "Device text, centered" in the browser's sans-serif font, centered in its field;
- the embedded-font field wrapped into "HI HO" / "OH IH" / "OHIO";
- the HTML field:
  - "Blue and bold" right-aligned, with "Blue" larger and blue and "bold" in bold;
  - "Second & last" centered, with "Second" underlined and "last" in italics;
  - a bullet before "Item";
- the bordered box grown to fit "Auto-sized box";
- the password field showing "******".

No page errors were logged. There is no pixel comparison against a reference player yet.

## Manual check on a real file (not a fixture)

This was a third-party SWF of unknown redistribution rights (`visita.swf`, 247 778 bytes). It is not included in the repository. With `node tests/inspect.js` it gives: CWS, SWF 6, 400×250, 24 fps, 20/20 frames, 169 top-level and 639 total tags, 6 sprites, 36 DoAction, and no diagnostics (Node 16 and Node 22).

In the player, headless Chrome draws its vector content (floor plans and frame borders) at frames 1, 10, and 20 with no page errors. With player 0.2, the JPEG bitmaps decode and draw (for example, the building at frame 3). The root runs its frame scripts and stops at frame 5, where the movie waits for a button. These are reported: `DefineEditText` and `DefineButton2` (not drawn); the AVM1 actions `ConstantPool`, `Push`, `GetVariable`, `GetMember`, `SetMember`, and `Not` (skipped); and `If`, which ends its script.

With player 0.3, hovering one of its three menu buttons (the building floors) shows the translucent cyan *over* highlight and the hand cursor. Pressing it runs `Push, GetVariable, Push, CallMethod` (for example `_root.gotoAndPlay(…)`). `CallMethod` is reported and ends the script, so the movie stays on frame 5 until the full AVM1 exists.

With player 0.4, its three `DefineEditText` fields decode. They use a device font, a `DefineFont2` named Verdana (bold) without glyphs. Their titles draw centered in bold: "Visita Virtual" from frame 1, and at frame 5 over the building. No text feature is reported as unsupported.
